# Contract generator

The generator follows the G0–G8 setup sheet at the beginning of `CONTRACT_TEMPLATE.pdf`. This sheet is input guidance only and is never included in an exported contract. The client-facing clauses after the sheet retain the previous template's wording; `shared/contract-template.json` also provides stable mappings for older drafts.

The editor uses the template's stable choice identifiers and semantic variable names. `shared/utils/contract-configuration.ts` defines labels, allowed values, dependencies, and required variables. It covers client status and consumer sales context, subscribed services, development and rights, hosting, SLA and support, maintenance and security, backups, duration, reversibility, and data processing. Branches disappear when their triggering service or option is inactive; their saved values are retained for later editing.

`shared/utils/contract-document.ts` composes the client document from the active configuration. It excludes unselected operational clauses, recalculates article numbers and annex references, includes only selected technical measures, and excludes professional late-payment penalties from consumer contracts. General clauses remain. A specific rights assignment receives its own detailed annex. Data processing requires a completed data-processing annex, whose letter follows the active annex order.

Export requires a contract reference and date, quote reference and issue date, an attached quote PDF, all active variables, consistent options, and the checks specified by G8. Unqualified data processing, undefined rights, missing SLA values, incomplete backup retention, unresolved placeholders, and missing applicable consumer / assignment / data-processing checks block export. Checks are cleared whenever the contract's fields, options, or quote change. Drafts can still be saved at any stage. The downloaded PDF fixes the chosen clauses and values and appends every page of the quote.

Contracts use schema version 2. Opening a version 1 draft copies its known values to semantic fields, retains **all** original values and the quote, and leaves the new choices and checks for review. Original values remain visible in the editor. Opening does not update the database; saving persists the upgraded draft. Version 1 drafts cannot be newly exported until reviewed under the updated configuration. No database migration is needed because contracts are stored as JSON.

Manual verification used headless Chrome with an isolated database: toggling hosting revealed its fields, inactive backup fields stayed hidden, numeric input produced no runtime errors, and uploading a real PDF filled both quote metadata fields. The form was visually checked at 1280 × 900 in dark mode and 390 × 844 in light mode, with no horizontal overflow on mobile. Automated coverage includes client profiles, conditional annexes and renumbering, export checks, old-draft preservation, PDF pagination and attachments, and authenticated save/reopen behavior.
